                          Finding this machine's network address…

                            Model provider

                            Which backend answers the assistant's chat/planner model. This is additive, not exclusive — OCR and semantic search below keep using Ollama regardless of what's picked here.

                            Chat model

                            The Ollama model the assistant thinks with. Must support tool-calling. Only used when the provider above is Ollama.

                            Ollama address

                            Where Ollama is running. Usually http://127.0.0.1:11434; point it at another machine on your home network to run inference there.

                            Watched folder

                            Documents dropped here are picked up automatically. Point this at a NAS or cloud-synced folder if you want the family archive to live somewhere durable.

                            Document OCR

                            Currently: built-in engine. The built-in engine (Tesseract) needs no setup. For higher-quality OCR of scans and photos, pick a local Ollama vision model such as glm-ocr:latest (pull it first with ollama pull glm-ocr:latest). Nothing leaves your machine either way. Best on a machine with a GPU: without one a page can take minutes, and an upload that runs over budget falls back to the built-in engine.

                            Voice input

                            The mic button in Chat transcribes speech with a local Whisper model — nothing leaves your machine after the one-time model download. Enter a Hugging Face model id: Xenova/whisper-tiny.en (fastest, English), Xenova/whisper-base (default), or Xenova/whisper-small (most accurate, slower on CPU).

                            Voice output

                            A "Read aloud" button on the assistant's replies speaks them with a local Kokoro voice — nothing leaves your machine after the one-time ~86 MB model download (the first click takes ~20s while it loads). Turn it off with FAMILY_AGENT_TTS=0 on the server.

                            Notifications

                            Shows a system notification when the assistant finishes a reply while you're not looking at that conversation — a private Chat reply, or an @agent reply in a family channel. Tapping it opens the reply.

                            Visual cards in chat

                            When on, the assistant can answer with a small generated chart, checklist, or diagram — an HTML snippet it writes, run in a sealed sandbox (no network, no access to the app). Generated code is less predictable than text, so turn this off for a strictly text-only experience.

                            Password vault

                            An encrypted store for the family's passwords and two-factor codes, unlocked with each person's own login password. Only the secret itself is encrypted at rest. Off by default — turn it on here to show the Vault tab on every client.

                            Internet access

                            Lets the assistant search the web and read pages to answer a question (the /web command and the research helper). Every request is SSRF-guarded, logged in Activity, and never followed through a redirect. Off means the assistant only ever uses what's on this machine.

                            Home name

                            Shown on the sign-in screen and to phones discovering this server on the network.

                            Background & startup

                            Closing this window keeps Family Agent running in the background (look for it in the tray) so other devices can still reach it — use Quit below to stop it completely.

                            Updates

                            Checks periodically in the background; when a new version is found it downloads, installs, and restarts on its own — no confirmation prompt. Restarting restarts the shared server too, so anyone using Family Agent on a phone reconnects in a few seconds.

                            Connections (MCP)

                            External services the assistant can call through the Model Context Protocol. A connection's tools are untrusted — the assistant treats their results as information only, never as instructions. HTTP servers are reached directly; stdio servers run sandboxed with no network unless you allow specific hosts. Enable with FAMILY_AGENT_MCP=1.
